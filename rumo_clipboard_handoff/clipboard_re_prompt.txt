# Rumo 的剪贴板技术设计候选方案：研究任务参考

## 1. 目的与当前状态

为片羽项目评估七类剪贴板技术设计。当前属于初步设计，具体方案待定。工作区中的文档与示意代码不能视为已实现、可运行或已验证的模块。

先阅读 docs/pinfeather_project_handoff.md，遵循已确认的产品方向。Rumo 是方案署名，片羽／Pinfeather 是产品名称。

## 2. 研究范围与方法

按专题评估设计，不要求把七类方案合并为一种架构：

- A：C++／Win32、OLE、焦点恢复、修饰键与多格式存储。
- B：C++／Qt、ECMAScript、CLI／IPC、动作与标签页。
- C：Kotlin Multiplatform／Compose、局域网发现、配对加密、OCR 与 MCP。
- D：Tauri／React、材料集合、参数模板、表单和跨进程大对象。
- E：.NET／Roslyn、动态宏、触发规则和文本清洗。
- F：Win32 键盘／消息事件、输入法、跨架构适配与队列粘贴。
- G：原生轻量常驻、较长历史、分页索引和生命周期。

有实际源码时，按真实入口追踪调用、状态与释放路径；有二进制且任务授权涵盖分析时，再选择 REA 或反编译器。没有相应资产时，给出候选设计与验证方法，不假定已完成源码分析、反编译或运行测试。

## 3. 关键技术专题

### 3.1 格式保真与载荷

- 评估 CF_UNICODETEXT、CF_HDROP、CF_DIB／DIBV5、HTML Format 与 RTF。
- 区分可持久化的注册格式、私有数据与依赖当前进程的句柄。
- 分析 WM_RENDERFORMAT／WM_RENDERALLFORMATS、读取阻塞和抓取线程。
- 对大图片和多文件评估分块、按需读取、落盘、哈希与大小限制。

### 3.2 监听与内部写入

- 比较 AddClipboardFormatListener、旧式监听链和轮询的适用范围。
- 定义内部写入来源识别、序列号、快照一致性和重复事件处理。
- 评估 OpenClipboard 占用时的有界重试、取消、失败提示和退出清理。

### 3.3 焦点与回贴

- 明确何时保存 GetForegroundWindow 及必要的子控件上下文。
- 评估 WS_EX_NOACTIVATE、面板隐藏和窗口恢复。
- 比较修饰键等待与合成 KeyUp，覆盖 IME Composition。
- 评估 WM_PASTE、SendInput 与目标应用差异；区分管理员窗口权限限制和系统架构位数。
- 检查激活和输入返回值；不把固定等待或成功注入按键当作目标应用已完成粘贴。

### 3.4 扩展与规则

- 明确脚本、CLI 和界面的能力契约及读写边界。
- 评估 OnClipboardChanged、BeforePaste、AfterPaste 的状态与顺序。
- 定义 Drop／Mangle 等动作作用于历史、流水线还是系统剪贴板。
- 文件、网络、系统命令、超时和终止需单独设计；动态编译不等于安全沙箱。

### 3.5 同步与配对

- 比较 mDNS／Bonjour、UDP 广播与固定地址。
- 定义设备身份、配对、密钥协商、AEAD、重放保护和撤销。
- 分开设计新增历史合并、同一条目更新、删除与系统剪贴板覆盖。
- 用双端并发、IP 漂移、断线、重连、重复投递和不同网络拓扑验证。

### 3.6 交互与 AI 协作

- 评估材料集合、参数表单、指令模板与 FIFO／LIFO 队列。
- 定义预览、取消、缺失参数、图文导出和回贴失败行为。
- 评估离线 OCR 的样本效果、队列及资源开销。
- 围绕用户开放的材料设计 CLI／MCP，明确访问范围、撤销、返回上限和真实客户端兼容性。

## 4. 输出要求

每项研究用以下结构，保留设计取舍、风险与验证方法：

1. 候选架构与模块职责：语言、依赖、模块及生命周期。
2. 重点机制与设计思路：流程、数据结构、接口设想和示意代码。
3. 关键技术机制：格式、监听、焦点、存储、扩展、同步与交互。
4. 预期收益与待验证问题：失败场景、原型任务及完成证据。

命令、类名和协议名称标为暂定示例；性能数字标为设计参考，具体指标待原型验证。已有引用可保留，事实与设计设想分开，不使用“独家”“生产级”“彻底杜绝”等词代替证据。

编译、模拟或 API 调用成功只能证明相应层面；尚未完成的客户端、部署和真实使用验证应分别说明。
