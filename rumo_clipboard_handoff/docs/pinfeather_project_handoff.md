## 4. 规划建议与版本路线

本节是规划工作基线，尚未实现；其中技术与交互细节属于建议，不能全部标为用户逐项确认。

### 4.1 产品结构

| 部分 | 用户能力 | 规划建议 |
| --- | --- | --- |
| 快捷面板 | 搜索、预览、选择与回贴 | 优先键盘操作、响应速度和可靠回贴 |
| 历史记录 | 自动保留复制过的内容 | 提供暂停、应用排除、删除和保留设置 |
| 材料集合 | 为一项任务挑选、排序和编辑片段 | 集合内容独立保留，避免历史自动清理导致任务材料消失 |
| 指令模板 | 复用常用要求，填写变化参数 | 和材料组合，交付前可预览完整文本 |
| CLI／MCP | AI 工具读取任务材料 | 与界面共用数据与访问规则，避免另建一套材料库 |
| 设备管理 | 配对与跨设备流转 | 状态可见，允许暂停同步和撤销配对 |

主要流程：复制内容 → 搜索或选入材料集合 → 整理顺序与指令 → 预览 → 复制、导出或由工具读取。有用的结果可由用户再次复制并收进集合；首轮不承诺自动抓取完整 AI 对话或迁移模型内部会话状态。

### 4.2 交付阶段

| 阶段 | 内容 | 进入下一阶段的条件 |
| --- | --- | --- |
| 内部试用：单机基础 | 文字、链接、图片历史；搜索、预览、收藏、删除；纯文本粘贴；托盘、快捷键、暂停与应用排除 | 浏览器、编辑器、终端和办公软件中完成复制、找回、回贴；重启后数据正确，无内部写入循环收录 |
| 首个公开预览：基础＋AI 协作 | 材料集合；多段合并复制与 Markdown 导出；参数化指令模板；最小 CLI 与 MCP 读取能力 | 同一集合可通过界面、导出与接口使用；模板结果可预览；至少在一个真实 MCP 客户端完成接入验收 |
| 后续预览：局域网互通 | 两台 Windows 配对；加密传输文字、链接和图片；同步新增条目，支持手动发送集合 | 断线重连无循环、无重复；撤销配对停止传输；远端接收不自动覆盖当前系统剪贴板 |
| 稳定版本 | 根据试用反馈打磨搜索、交互、性能、备份、升级与恢复 | 连续真实使用一周并关闭关键问题；完成备份恢复与升级验证 |

按验收结果推进，不承诺未经估算的日历工期。三项 AI 能力都进入公开预览范围，但先完成共同的一条小流程，避免各自扩展成独立平台。

### 4.3 建议的首轮边界

- 本地优先；初期无需内置模型服务或付费 API 才能使用核心功能。
- 材料拼接与模板先覆盖文字、链接；图片支持历史预览、独立复制和导出。图文混合投递需要按目标工具验证。
- CLI 先提供集合列表、读取与导出。MCP 先提供用户开放集合的只读访问，普通历史默认不对 AI 工具开放；暂不提供自动粘贴、删除或任意脚本执行接口。
- MCP 本地 stdio 是传输候选，不等于授权机制；仍需定义本地调用者、可读集合、撤销开放及应用退出时的行为。
- 同步先传新增条目和主动发送的集合；初期不传播删除操作。远端材料先进入历史，由用户决定是否复制到当前系统剪贴板。
- 手机、其他桌面平台、互联网同步、完整对话迁移、插件市场、通用脚本引擎、OCR 与语义搜索后续再评估。

## 5. 原 MVP 技术评审

结论：元数据与载荷分离、事件监听、界面与后台工作解耦、大对象避免经 JSON 全量传给前端、参数模板和 AI 工具接口，都有继续深化的价值。当前规格与骨架存在实施前必须解决的问题。

这里的 P1 表示照此实现会破坏关键行为或安全边界，P2 表示重要设计或证据缺口。项目尚未运行，这些是文档及示例代码层面的发现，不是线上故障报告。候选文档对部分风险的措辞已补充说明，以下 R1–R8 仍保留为待解决的实施问题。

### R1 · P1：回贴可能发到错误窗口并报告成功

- 位置：[MVP][mvp] 第 193–249、280–301 行。
- 证据：忽略窗口激活与输入注入返回值，固定等待 20ms 后发送 Ctrl＋V，最终直接返回成功。
- 触发与影响：目标激活失败、用户切换前台窗口、目标权限高于自身时，可能粘贴失败或发往错误窗口，却被报告成功。
- 修正方向：记录并校验目标；有界等待修饰键释放；注入前复核前台目标；检查注入数量。失败时停止自动回贴，保留材料供手动粘贴。按键成功注入仍不能等同于目标应用已消费内容。
- 默认路径不采用修改系统前台锁设置、强制清空用户按键或清除输入法未提交文本。管理员窗口的支持边界需另行明确。
- 依据：微软说明 [SetForegroundWindow 可能被拒绝][ms-foreground]，[SendInput 返回插入事件数量且受 UIPI 限制][ms-sendinput]。

### R2 · P1：三阶段布尔保护无法保证不漏记、不自激

- 位置：[MVP][mvp] 第 106–151 行。
- 证据：先更新 `last_seq`，再根据全局布尔值丢弃事件；保护区退出即清除标志，没有绑定具体写入的来源识别。监听窗口和抓取方法仍为空实现。
- 触发与影响：外部复制恰好发生在内部操作期间会被误丢弃；异步通知晚于保护区退出时，仅靠布尔值无法判断来源。抓取失败后的重试和退出清理也未定义。
- 修正方向：补充内部写入标记、快照一致性检查、有界重试、队列边界、监听线程与隐藏窗口的创建和销毁责任。避免用固定时间窗或全局忙状态替代事件来源识别。
- 依据：[剪贴板序列号用于追踪变化][ms-sequence]，不能单独证明内容来源、读取成功或目标应用完成粘贴。

### R3 · P1：多格式载荷关系未表达完整

- 位置：[MVP][mvp] 第 486–499 行；对照[方案 A][plan-a]第 169–174 行。
- 证据：载荷表只有 `id PRIMARY KEY、format、data`，没有明确的历史条目关联字段。若 `id` 等于历史条目 ID，则一条记录只能保存一种格式；若为独立载荷 ID，则关联关系缺失。方案 A 已描述一对多关系，综合规格没有保留下来。
- 触发与影响：同一复制内容包含纯文本、HTML 等格式时，无法按现有说明完整关联保存并恢复。
- 修正方向：明确条目与多份格式载荷的关系、写入原子性和删除清理；为格式恢复与历史清理设计测试，再确定具体 schema。

### R4 · P1：AI 材料访问边界缺失

- 位置：[MVP][mvp] 第 398–445 行；[方案 C][plan-c]第 67–73 行。
- 证据：MVP 工具面向完整历史检索与剪贴板回写，没有定义可读材料范围、撤销开放、调用身份和响应上限。方案 C 已将 `destructiveHint` 说明为行为注解，并把权限列为待设计，但尚未形成可实施的访问控制。
- 触发与影响：若直接接入真实数据，调用者获得哪些历史内容没有明确边界；把注解当确认机制会遗漏实际权限控制。
- 修正方向：围绕用户开放的材料集合设计，逐次检查有效范围；读写权限分离，明确数量及内容大小上限。传输和工具注解不替代访问控制；材料经接口交付后，目标 AI 工具可能再发给其模型服务。
- 依据：[MCP 工具规范][mcp-tools]明确区分工具元数据与调用控制，并要求不能盲目信任工具注解。

### R5 · P1：MCP 示例不是可用的接入实现

- 位置：[MVP][mvp] 第 407–480 行。
- 证据：`search_clipboard` 返回固定示例；列出的 `copy_to_clipboard` 没有对应执行分支；没有实际传输与协议协商实现。
- 触发与影响：按此示例接入真实客户端，不能得到文档宣称的历史检索、回写和标准服务能力。
- 修正方向：根据目标客户端支持的协议版本使用合适 SDK；公开工具必须具备真实执行路径、输入验证和一致的错误语义，并完成客户端接入验证。

### R6 · P2：FTS5 没有定义中文与短词检索行为

- 位置：[MVP][mvp] 第 500–501 行。
- 证据：只声明 FTS5 和毫秒级多关键词词缀检索，没有分词、短词、URL、代码标识符或查询转义策略。默认分词与 trigram 的内存实验均暴露匹配边界，结果见第 6 节。
- 触发与影响：用户用句子中的中文片段搜索时，可能找不到已保存内容。
- 修正方向：先定义搜索体验与样本，覆盖中文一至两个字、较长片段、英文、代码和链接，再选择索引及必要的降级查询；结合数据规模验证速度。[SQLite FTS5 官方说明][sqlite-fts5]可作为边界依据。

### R7 · P2：性能目标和依赖拼装缺少验证

- 位置：[MVP][mvp] 第 15、22、37–39 行；[方案 G][plan-g]第 55–59 行。
- 证据：12–18MB 常驻内存、低于 50ms 面板响应没有统计口径或测量；Rust 存储层直接列入 MemoryPack，没有适配方案。
- 影响：实现者容易按未经证明的预算选型，或将其他运行时的组件与性能结论直接搬入 Rust。
- 修正方向：Rust＋Tauri＋React/TypeScript、SQLite 保留为候选，先做纵向原型；测量冷启动、热唤出、隐藏与显示状态，并统计相关 WebView 进程和内存口径。MemoryPack 不作为默认 Rust 依赖。
- 依据：[Tauri 为多进程架构][tauri-process]；[MemoryPack 主要面向 C#／Unity][memorypack]。工作集裁剪会减少当前驻留物理页，[不等于释放应用已分配的数据或降低整体开销][ms-working-set]。

### R8 · P1：方案 F 使用错误钩子编号

- 位置：[方案 F][plan-f]第 40–42 行及同一代码块的重试分支。
- 证据：注释称安装 `WH_KEYBOARD_LL`，实际传入 `10`；微软定义 `10` 为 `WH_SHELL`，`WH_KEYBOARD_LL` 为 `13`。
- 影响：照抄后注册的钩子及回调消息语义与设计不符，不能按低级键盘钩子处理。
- 修正方向：使用具名常量，并验证回调签名、生命周期和目标范围；不能只替换数字就宣称整个钩子方案通过。[微软常量定义][ms-hooks]。

## 6. 已有证据与未验证范围

### 6.1 已完成的检查

- 对全部本地文字材料完成静态阅读，并对上列发现核对源文件行号。
- 查阅文中链接的微软、SQLite、Tauri、MemoryPack 和 MCP 官方资料。

| 实验 | 结果 | 能证明什么 |
| --- | --- | --- |
| 按 MVP 的一对一解释建载荷表，同一 `id=1` 写入纯文本后再写 HTML | `UNIQUE constraint failed: clips_payload.id` | 此解释不能保存同条目的第二种格式；不代表执行过真实产品 schema |
| 默认 FTS5 保存“今天讨论剪贴板项目定位”，查询完整句子 | 匹配 1 条 | 实验数据确实入库 |
| 同一默认索引查询“剪贴板”“项目定位” | 均匹配 0 条 | 默认分词不能直接满足这类中文片段检索 |
