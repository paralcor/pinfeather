# Rumo 的剪贴板技术设计候选方案 C：局域网同步、OCR 与 MCP

状态：初步设计，具体方案待定。本文是 Rumo 整理、供片羽项目评估的技术设计候选方案；模块划分、平台范围、接口和性能需要通过原型验证后确定。

下文模块名为暂定设计名称，代码块为示意代码，不代表已有实现。技术风险与待验证问题见[项目交接说明](pinfeather_project_handoff.md#5-原-mvp-技术评审)。

## 1. 候选架构与模块职责

拟评估 Kotlin Multiplatform／Compose Multiplatform 下的局域网同步、离线 OCR 和 AI 工具接入。Windows、macOS、Linux 为架构参考范围；片羽先验证两台 Windows 的流转，其他平台不因本文自动进入首版。

### 1.1 技术栈设想

- 界面与语言候选：Kotlin、KMP、Compose Multiplatform。
- 网络候选：异步 HTTP 服务、mDNS／DNS-SD 发现及备用单播连接。
- MCP 候选：标准 SDK；传输与协议版本按目标客户端验证。
- OCR 候选：通过 JNI 接入本地 C++ 引擎。
- 存储候选：带全文检索的嵌入式数据库。

### 1.2 候选模块与职责

| 暂定模块名 | 拟承担的职责 |
| --- | --- |
| `McpToolProvider` | 提供材料检索、读取及可选写入工具，具体工具集待定 |

## 2. 重点机制与设计思路

### 2.1 设备发现与配对设想

需验证组播丢包、AP 隔离、移动热点、多网卡、IP 漂移和虚拟机网络中的连接行为，并防止未授权设备访问材料。

#### 备用地址交换

可在配对及同步请求中携带本机候选地址：

```text
[发起端 Device A] ──POST /sync/pairing/v3/intent──> [接收端 Device B]
   Header: rumo-sync-info: <Base64(本地所有有效网卡IP + 端口 + 实例ID)>
```

`rumo-sync-info` 及示例路径是暂定协议名称，不是片羽现有接口。接收方可尝试单播连接，但地址交换不保证 NAT、路由、防火墙或 AP 隔离下可达；地址可信度与连接策略待设计。

#### 三阶段配对

`Pairing V3` 是这份草案中的暂定设计名，不表示协议已有发布版本。

- Intent：交换随机数 `nonce` 与设备信息，建立待配对上下文。
- Proof：评估 SAS 或六位码的认证交互；密钥协商、HMAC 使用方式、尝试限制和身份绑定待定。
- Commit：确认配对并建立传输密钥，评估 AES-GCM 或 ChaCha20-Poly1305。

重放保护、密钥保存、撤销配对及故障恢复需要补齐，不能仅凭三阶段名称或算法列表认定配对安全。

### 2.2 离线 OCR 与 AI 工具接入

OCR 结果可作为材料的可检索文本；MCP 可提供访问入口，二者按需要组合，是否同时启用待定。

#### OCR 流水线

- 可直接加载本地 C++ 动态库，评估避免独立 Python／Node 进程的部署方式；总体资源占用待测。
- 页面模式 6 可作为单一文本块截图的实验选项，识别效果需与其他模式按样本比较。
- 可通过互斥与任务队列协调底层指针；队列上限、取消、引擎销毁和失败恢复待设计，互斥不等于内存安全保证。

#### MCP 工具设想

- `search_clipboard`：候选过滤项包括关键词、类型、标签和时间；类型参考 `text, link, image, rtf, html, color, file`。
- `get_paste_item`：根据 ID 读取开放范围内的条目与格式。
- `add_to_clipboard`：可选写入能力，是否提供及授权方式待定。

`readOnlyHint`、`destructiveHint` 仅描述工具行为，不代替授权。片羽首轮建议只开放用户选择的材料集合，普通历史和写入能力分别设定边界。

## 3. 关键技术机制

### 3.1 数据模型与文件索引

条目可关联集合、标签及多格式载荷。多文件复制可保存索引树并分块计算哈希，避免全量驻留；是否复制文件本体、路径失效和文件变更的处理待定。

### 3.2 并发同步与冲突处理

可评估逻辑时钟、LWW 和设备唯一标识的组合。新增条目合并、同一条目的更新、删除以及当前系统剪贴板覆盖需要分别定义；最终一致性、防循环和重连行为需两机实测。

## 4. 预期收益与待验证问题

- 验证材料通过 MCP 交付给真实客户端的流程，明确权限撤销和响应大小上限。
- 验证发现、地址交换和连接失败的降级，不把可交换地址当成可达性证明。
- 测量 OCR 识别效果、任务积压与资源占用；加密配对和断线恢复另行完成安全与故障测试。
