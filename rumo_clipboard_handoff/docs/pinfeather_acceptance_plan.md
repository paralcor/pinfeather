## 1. 证据层次与完成状态

| 状态 | 含义 | 能否勾选原首轮完成项 |
| --- | --- | --- |
| 未运行 | 无执行记录 | 不能 |
| 失败 | 断言/真实行为不符；保留原始结果 | 不能 |
| 待人工 | 自动部分可检查，但缺用户真实应用操作 | 不能把整项勾选 |
| 代码可review | 编译及相关自动行为测试通过，等待独立review或真机 | 不能外推整项完成 |
| 本机通过 | 指定构建、系统、应用/输入法配置下真实复现通过 | 只勾证据覆盖部分 |
| 未覆盖 | 无对应版本/设备或该规模未测 | 不宣称兼容/性能达标 |

自动测试必须调用同一生产规则、schema、parser或状态机。允许替换底层Win32 API返回以触发失败，但不能mock被测状态机本身。模拟网页回贴、假IPC和固定返回只属于相应UI测试，不能替代宿主装配或真实控件消费。

风险重点：错窗口与权限/IME误判可能泄露材料；内部来源错误/不一致快照会漏记或自录；提交/退出竞争可能造成落盘误报。对这些路径使用失败先行测试、可控时钟/barrier和真实SQLite故障回滚证据，最后一次改动后做一次新检查。不能用宽泛catch、空测试集合或跳过失败来变绿。

## 2. 每次运行必须记录

- run_id、工作包/E任务、完整方案版本；基线HEAD、dirty文件hash或构建源码指纹；exe SHA256及debug/release。
- Windows edition/display version/build/UBR/架构；目标应用版本/位数、终端粘贴绑定；WebView2实际加载版本；输入法配置。
- 测试或人工操作的合成输入、预期/实际、起止条件、步骤、结果、日志/CSV路径。
- 所有命令、工作目录、退出码、测试名称/数量、失败与修复原因；未运行命令明确列出。
- 当前执行者身份：客户端版本、可见模型标识、provider 非秘密别名、实际审批/沙箱与身份确认边界；不记录 key 或秘密配置。历史报告沿用原 Claude/Mimo 身份。
- 如实际使用了子agent，记录 ID/任务/可见模型/权限证据及主负责人如何复核其结论；未用则如实写未用。

正式结果只使用合成内容；诊断记录禁止全文、token、私人窗口标题。截屏前清理测试UI中的私人内容；网页截图仅无头，Windows验收截图由用户提供或明确授权，不接管鼠标键盘。

以下目标由各E任务创建；现在不存在的命令/target不得写成已验证。首次建工程后把最终命令补入开发文档，并记录工具版本。

| --- | --- |
| npm run typecheck | TS镜像/前端调用错误 |
| npm run test | 搜索乱序、组合输入、选中/预览状态、失败显示和配置ACK |

| 同上 --test store_contract | 多格式事务、容量/幂等、版本拒绝、回滚/级联、重开 |

| cargo fmt --manifest-path src-tauri/Cargo.toml -- --check | 格式差异 |
| cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets -- -D warnings | 实际配置下静态风险；不能当运行验收 |
| npm run tauri -- build --no-bundle | release宿主与本地资源装配，不制作/安装MSI |
| git diff --check | 已跟踪改动空白；不自动包含未跟踪文件 |

`capture_windows`另列为ignored原生集成target，只在用户确认隔离环境后手动启动：先明确设置`PINFEATHER_ALLOW_SYSTEM_CLIPBOARD_TESTS=1`及本次新建`PINFEATHER_TEST_DATA_ROOT`，再运行`cargo test --manifest-path src-tauri/Cargo.toml --features test-fixtures --test capture_windows -- --ignored --test-threads=1`。它通过`CARGO_BIN_EXE_pinfeather`定位产品worker，使用合成载荷但会替换系统剪贴板；不能由普通test脚本或agent自动跑，不与已运行宿主并行。未获环境/授权时写未运行，不写通过。此target可验证真实内部write→监听→来源分类，不需要给产品增加任意写入命令。

Rust依赖与PATH由执行启动脚本管理；不默认全局配置。每个命令检查测试清单与数目，测试筛选跑0个/ignored未执行/编译target缺失均不是通过。性能测试显式ignored且在P3单独运行，不误算常规测试数。

至少做三次针对性反证：把来源判断临时改成“文本相等即内部”、把搜索临时改成“只查preview”、把目标变化后的返回临时改成成功。每次先在archive保存精确文件副本，再只改一项，要求对应测试失败，恢复精确内容后重跑；不改断言、不用git restore丢掉未提交工作。该过程不触碰系统剪贴板或目标窗口。

## 8. Release测量

### P1 · 环境与可重复性

记录CPU、物理内存、系统/存储类型、构建flags、exe SHA256、WebView2实际版本、数据规模和负载条件。Vite/dev server和debug数据另列。不能升级Rust/Windows、裁剪工作集或关闭用户应用来制造对比，必要条件变化先记录。

应用将WebView2用户数据目录显式放在当前隔离data-dir下的webview子目录，两个窗口共享该目录。这样既不污染其他配置，也为PID归属提供佐证；独立采样仍以真实进程关系/创建时间为准。

### P2 · 冷启动与热唤出

- cold run：本应用宿主/worker/归属WebView2全部退出，从启动进程开始，到原生快捷入口可用、到首屏真实内容可交互两个时点。至少10次，逐次值、中位数和最大值；“OS重启后的首次”单列，不能把新进程启动称为机器冷缓存。
- hot run：后台已驻留，用户实际触发热键到可输入及首批结果可选，至少50次；记录p50/p95/最大值、预热与数据规模。若只由内部测试命令打开窗口，则另外列“内部唤出路径”，不替代热键延迟。
- 使用宿主单调时钟加panel_ready ACK，记录每段及总体；ACK只能在React已提交真实结果和输入可用后发，不能页面脚本刚加载就发。
- 测量本身不自动发送系统热键。用户手动触发、后台只读记录；少于规定次数明确未完成，不插值补齐。

### P3 · 搜索规模

独立测试库固定种子，1k/10k/100k各一份。基础长度分布：70% 128字、25% 2KiB、5% 32KiB；固定位置嵌入中文、代码/URL和字面特殊字符，每类查询都维护预期fixture_id集合。测试专用容量可以大于正常应用上限，不修改产品10k/256MiB限制。

每类先一次冷查询另列，再预热5次、采30次，记录Rust/SQLite查询耗时p50/p95/最大值、命中集合正确性和返回摘要字节数；页大小固定50。使用 `cargo test --release --manifest-path src-tauri/Cargo.toml --test search_benchmark -- --ignored --nocapture` 显式运行并把逐次数据放archive。

前端可见延迟在真实宿主允许的数据规模上测，从输入事件到当前代次结果提交可交互；分别报告防抖、IPC/查询和渲染。100k若只有存储测试，没有接上同一UI，则如实标“100k UI未测”，不能拿后端耗时当用户可见延迟。并发/新写入负载单列，不混入基本结果。

### P4 · 总内存和资源归属

`tools/measure-processes.ps1` 只读采样：宿主、临时worker和该隔离WebView2的browser/renderer/GPU/utility等进程。优先跟踪宿主进程树，并结合创建时间、已知worker句柄与独占user-data-dir校验；PID复用必须被识别，不能只用进程名，也不能累加每个窗口的同一browser进程两次。

至少每1秒一采，记录UTC时间、场景、PID/PPID/创建时间/角色、WorkingSet64、PrivateMemorySize64；汇总每时点去重总和。工作集求和含共享页重复计算的限制，Private Bytes与实际物理占用不同，均在报告注明。短于采样周期的worker峰值可能遗漏，记录限制；可加100ms短时专项采样，但不把1s数据写成精确全程峰值。

场景：启动后稳定、隐藏空闲、面板显示、连续100次复制/搜索后、反复开关50次后。每场景至少60秒，末30秒作为稳定窗口，报告中位/最大和进程数；采样前置条件由用户完成，不自动操纵真实前台或输入。

若出现父进程信息缺失/权限阻止/未知WebView2归属，单列未确认PID与无法得出总量的原因；不为了填“总内存”把其他应用混进去或漏掉GPU/worker。没有可靠归属就不宣称总内存已测。
