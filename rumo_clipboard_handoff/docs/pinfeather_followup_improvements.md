# 实现与原设计的差距及后续改进

本清单区分源码实现、离线检查、合成现场和个人日用；通过某一层不代表其余层通过。历史带日期的验收记录保留原结论，不据新增功能补填完整 M1、T5、P1–P4 或首轮完成。

## 当前能力与证据

当前路径是“复制保存 → 搜索 → 快捷面板查看 → 明确复制 → 用户手动粘贴”。已具备暂停、最小应用排除、托盘/退出、按条删除、确认清空、历史备份和仅恢复到新目录的工具。管理能力有合成数据现场及离线库核对；这不是完整个人日用或全部应用兼容性验收。

历史列表限高、两行摘要、追加保位及方向键内部定位已实现；返回顶部为整页滚动超过200px时出现的右下角按钮，仅回整页，保留内部列表/正文位置，不主动修改查询或选择。新候选的原生窗口和个人实际使用结果仍待报告；无头合成检查不能代替它们。输入法正常提交仍交给既有处理，不承诺焦点转移时冻结合法的组词提交。

## 与首轮及界面原型的差距

| 设计目标 | 当前差距 | 后续动作与完成标准 |
| --- | --- | --- |
| T0–T3：范围、规格、收录及搜索基础 | 基础任务已有验收，完整平台/数据规模矩阵未完成 | 保留基础4/7口径；条目数不是代码量或总工作量百分比 |
| T4：快捷键唤出并回贴原应用 | 目前为明确复制后手动粘贴，自动回贴延期；部分键盘/IME及目标切换矩阵未完整收口 | 先稳定手动路径；重新决定自动回贴范围后验证目标变化、权限、修饰键和IME失败路径，不从复制成功推断目标已粘贴 |
| T5：完整驻留与生命周期 | 最小驻留和有限退出已有证据；完整重复启动、异常退出、待写任务及所属进程回收矩阵未全部验收 | 补齐缺口，明确根进程退出与全部所属进程退休的区别；正常退出码0不等于全树退休 |
| T6：跨应用与性能基线 | 已有部分基线和工具证据，完整浏览器/编辑器/终端矩阵、搜索规模和资源口径未收口 | 复用仍有效证据，仅补缺项；测量包含所属WebView2并明确未测规模，不承诺未经测量的启动/内存数字 |
| 可独立个人日用 | 已提供默认暂停的桌面入口和独立目录；尚无完整的个人退出重开、长期可靠性及排除规则反馈 | 由用户以少量非敏感文字验证退出重开保留，再持续试用；代理诊断个人库另定读取范围，不自动清理、迁移或导出 |
| 原型布局、密度与组件体系 | 现有界面主要是React和手写CSS，复用主题变量；未完整采用原型的shadcn/ui Nova、分栏、密度与整理工作台，不称为原型已完整还原 | 先按使用频率梳理信息层级与窄窗问题，再确认组件/依赖及布局改造范围；不因本清单自动安装依赖或重写界面 |
| 历史量增加时仍易用 | 限高解决页面持续增长，加载更多仍把条目追加进DOM；没有虚拟列表或大规模性能承诺 | 实际规模测量后决定是否需要虚拟化或真正分页；不能用限高等同于解决无限量内存/渲染成本 |
| 窄窗和缩放 | 无头检查中320px宽、200% CSS缩放时，空状态页面的列表外工具区仍有横向溢出；历史列表优化未消除此问题 | 在新合成界面复现，调整控件换行及布局，验证全页无横向遮挡；同时补原生WebView2/DPI观察，CSS缩放不等于系统DPI验收 |
| 集合、收藏、模板、Markdown导出、CLI/MCP、局域网同步 | 未实现，不属于首轮单机链路的必做范围；部分也属于内部试用或后续预览 | 继续后置，分别确认数据/权限/同步契约及验收，不把这些缺项混成首轮失败或当前已完成 |

## 后续改进顺序

1. **个人基本闭环**：确认新候选的列表与回顶体验、退出重开后的数据保留、暂停及必要应用排除；出现数据可靠性或隐私边界问题先停止扩展。
2. **易用性与驻留**：根据真实反馈处理窄窗/缩放、信息密度、键盘路径和T5生命周期缺口。任何个人库读取、修复或删除都按具体范围授权。
3. **矩阵与性能**：补齐T6缺失应用/规模/资源证据，优先复现真实问题，不重复已通过且输入未变的现场。
4. **后续能力取舍**：再决定自动回贴及原型组件/分栏改造；集合、模板、AI接口与同步保持独立阶段，不自动并入维护修复。

源码提交、构建、推送和实际试用分别报告；推送成功不代表安装、原生验收或产品阶段完成。当前策略保留旧候选和回退入口，不自动替换正在运行的实例。
