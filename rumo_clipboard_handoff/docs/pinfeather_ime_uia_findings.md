# IME 只读 UIA 研究：本机结果与待验边界

更新日期：2026-11-01（UTC+08:00）。研究目标是验证自动回贴前能否可靠判断输入法组词状态。当前结果不解除 W0 的 IME 子关卡或 W3 自动回贴限制，不改变已验收的基础收录和搜索能力。

## 本机结果

研究使用独立归档中的 Windows UIA 诊断器，未接入产品宿主。真实输入均由用户在 Edge 合成输入框中使用微软拼音完成；诊断器只读取焦点、身份、HRESULT、接口/范围对象存在性，不读取正文、候选或范围长度，不注入输入或操作剪贴板。

| 人工准备状态 | 接口与范围查询 | 结果边界 |
| --- | --- | --- |
| 空白输入框 | TextEditPattern 接口存在；两个范围查询成功、对象均为 null | 一次有效 idle 观测 |
| 未提交候选，用户确认原位静置 20 秒且无其他操作 | 两个范围查询成功、对象均非 null | 一次受控组词正样本 |
| 按空格提交，用户确认候选消失、文字进入框内并静置 20 秒 | 两个范围查询成功、对象仍均非 null | 提交后恢复为空的预期未通过 |

另一次组词尝试中用户在结束提示前拖动窗口、候选消失，无法确定与采样的重叠时间；该 raw 保留为有效接口观测，不计受控正样本。

上述成功协议观测均为普通权限，目标 PID/创建时间、父子窗口锚点、前后 Win32 快照、两次 UIA 焦点和对象比较通过，子进程在 5 秒监督内正常退出，实际记录耗时 31–47ms。每轮使用新准备确认、完整 8 秒手动切回窗口及单次执行，无自动重试。

**范围对象存在不能直接等同于当前正在组词。** 用户确认已提交时仍取得非 null 对象，说明仅凭该信号尚不能可靠区分组词与提交后的状态。raw 的 ime_judgement 保留为 none，不把未知或矛盾结果改成未组合。

## 诊断器验证

R2e-fix2 的离线审查通过 84 项回归、13 项独立对照及 16 项焦点归属边界对照；48 个逻辑断言包含在回归的一项内。R2f-fix4 的离线审查通过 95 项回归及 21 项独立对照；51 个逻辑断言包含在回归的一项内。回归与真实桌面观测分别计证据。

R2f 的单次真实焦点诊断取得 ControlType=50004、IsKeyboardFocusable=true，补读前后焦点均为 true，三份 Win32 快照一致；历史焦点 false 的原因未确定。其后快照时间顺序具有源码、编译和一次正常路径运行记录，毫秒同值不提供更细调用顺序分辨率。skip 分支覆盖仍来自源码、共享比较函数和镜像 emitter，不能声称已直接运行诊断器 skip 分支。

研究源码、二进制和旧证据按哈希冻结。旧 fix2 四个 exe 曾被贡献者在 fix3 提前编译覆盖，原物来源受损；fix4 及后续实采确认它们未再次变化，不声称已恢复原物。

## 上游解释路径

固定 Chromium 提交 `2dca33025a6310ce8846070e902f7a48f3a89de4` 中，提交路径把提交范围交给可访问性节点，节点缓存范围，两个查询共用同一个缓存读取函数。该路径提示提交后的缓存残留可能影响范围存在性；两个查询的一致结果不是两个独立来源。[提交通知](https://github.com/chromium/chromium/blob/2dca33025a6310ce8846070e902f7a48f3a89de4/ui/base/ime/win/tsf_text_store.cc#L1659)、[节点缓存](https://github.com/chromium/chromium/blob/2dca33025a6310ce8846070e902f7a48f3a89de4/ui/accessibility/platform/ax_platform_node_win.cc#L810)、[共同读取路径](https://github.com/chromium/chromium/blob/2dca33025a6310ce8846070e902f7a48f3a89de4/ui/accessibility/platform/ax_platform_node_textprovider_win.cc#L300)。

这是上游实现证据，尚未证明本机根因：该提交 chrome/VERSION 为 158.0.8113.0，本轮磁盘 Edge 文件版本为 156.0.4314.42，未建立已加载二进制与该提交的对应。需要继续区分缓存、通知时序及具体 provider 版本；不得据此宣称 Edge 缺陷已定位或已修复。

## 当前决定与后续

基础收录、搜索及其既有验收不变。自动回贴继续遵守 IME 未知时不执行的现有规则；快捷面板/热键等任务是否先行，按已确认任务依赖与用户授权执行，不把本次研究描述为整个项目停止。

下一步先只读核对本机版本对应实现与提交清理路径，再设计有区分力的实验。取消、焦点/目标切换、冷启动、失效路径及 VS Code/Terminal 的该 UIA 路线尚未验证；不继续盲目重复同一采样，也不把一条正样本当作全部目标可用。

## 2026-11-01：schema9 I00 补充结果

新一轮目标身份更新后，v13 单次 I00 取得有效 schema9 协议，但首次 UIA 元素没有键盘焦点，两次元素比较不同，焦点归属未通过。TextEdit 和两个 IME 范围方法均未调用，没有形成新的组词判断；自持进程退出码 0 不代表正常原生资源清理已验收。

离线修复、目标更新、实际观测、摘要及消耗状态见 [schema9 I00 结果记录](pinfeather_ime_i00_schema9_results.md)。该记录不代表诊断代码已集成产品，F2 仍为 partial、首轮基础 4/7、自动回贴关闭。

后续离线对照发现，旧父流程会误收协议合法、首次归属成功但最终状态为 stale 的记录。v14 候选补上最终状态检查，168 项离线测试及封包校验通过；没有新增现场采样，原焦点原因仍未知。具体复现、兼容边界及证据索引见上述记录。

独立焦点补读路线随后完成 [wire10 与 F00 离线验证](pinfeather_focus_wire10_offline_results.md)：原 R2f 的 32 层有效模型超过 4KiB，新编码保留原始字段并拒绝超限、混版和矛盾 skip。独立 F00 单次父流程及默认关闭封包通过 133 项离线方法；首次归属 false 的稳定诊断可留证，仍不产生 I00/IME 许可。新探针只构建未运行，没有新增现场许可或 IME 结论。
