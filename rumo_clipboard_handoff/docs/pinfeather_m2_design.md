# M2 最小设计：驻留、可见状态与应用排除

状态：2026-11-02，两个切片均已实现并通过负责人独立离线复核；普通 Windows x64 候选的托盘、暂停、持久排除、显式复制、退出与重启核心现场通过。完整故障/恢复与兼容矩阵未覆盖，整体 M2/T5 尚未验收。Git 基线为 `ef3b1ed28ff6ab3dda4d67e666614670031f6274`，本地提交状态以 Git 记录为准。当前证据、限制及候选身份统一见[验收记录](pinfeather_acceptance_plan.md#m2-core-field)；剩余任务见[手动版收尾顺序](pinfeather_execution_tasks.md#manual-delivery-closeout)。

## 目标与范围

用户能够隐藏主窗口后继续使用片羽，从托盘打开窗口、查看收录状态、暂停或开始收录，并明确退出；主窗口提供最小应用排除及生效反馈。

沿用[手动 M1 契约](pinfeather_explicit_copy_stage.md#manual-m1)：完成输入、独立浏览、显式复制；复制后面板保持打开。启动显示主窗口，收录默认暂停，用户主动开始；隐藏与重新打开窗口不改变收录开关。仍要求显式 `--data-dir`。

本增量不含自动回贴、开机启动、热键编辑、默认生产数据目录、同步、模板、CLI/MCP、历史清理、强制放弃未保存内容或数据库迁移。同目录二次启动唤起留在 E13 后续范围；现有第二宿主拒绝启动行为保持，不将本增量称为完整 W4/T5。

## 窗口、托盘与退出

驻留状态、收录状态分别由单一所有者管理：新增小型 `residency.rs` 持有托盘及应用退出过程；`HostRuntime/CaptureState` 继续拥有收录、队列、提交和资源回收；`PanelHost` 继续拥有面板会话与热键。前端和托盘只发意图、显示宿主确认值，不各自维护收录开关。

| 条件与动作 | 结果 |
| --- | --- |
| 正常启动 | 主窗口可见、收录暂停；托盘创建成功后才允许隐藏到托盘 |
| 托盘可用时 main X | 只隐藏主窗口；不停止面板、热键、监听或存储，不改变收录状态 |
| 托盘初始化失败或已知不可用时 main X | 保持可见，提示“托盘不可用，请使用退出片羽”；不把失败变成无入口后台驻留 |
| 托盘“打开主窗口” | 显示并聚焦已有窗口；错误保留在托盘可见反馈中，不新建第二宿主 |
| 托盘“打开快捷面板” | 调用现有 PanelSessions.open，保留 M1 会话握手与清空规则 |
| 托盘或主窗口“退出片羽” | 进入同一退出流程；首先显示主窗口的退出状态，再开始关闭 |
| stopping 期间重复退出或 X | 合并到当前退出任务；不创建第二个关闭任务，也不隐藏错误入口 |
| 关闭成功 | 所有必要关闭结果确认后，才调用 Tauri exit；预期 ExitRequested 不重复清理 |
| 关闭失败或未完成 | 主窗口保持可见，显示未保存数量和失败类别；提供重试保存/重试退出，禁止恢复收录和新复制 |

托盘菜单最小集合：打开主窗口、打开快捷面板、收录状态、暂停/开始收录、退出片羽。状态用文字表达，不仅靠图标颜色。错误或过载显示实际原因和“打开主窗口处理”，不把失败菜单写成普通“已暂停”。

应用退出状态为 `running -> stopping -> exited`，失败为 `stopping -> failed -> stopping`。failed 是退出未完成，不是可继续正常运行；不自动重新启用面板或收录。启动局部失败也使用同一个资源所有者回收；系统强制终止不承诺队列保存。

关闭先封闭新面板会话、复制和策略更新，再撤销新的写入借用、停止新观察，停止热键及抓取工作，排空已接纳且仍符合策略的队列，等待在途 writer 完成及其析构、来源登记，再释放监听窗口、存储线程和托盘。不得用 `set_enabled(false)` 代替退出，否则会取消本应排空的队列。

各独立资源关闭都必须被尝试和汇总；面板隐藏或热键停止失败不能跳过宿主关闭，也不能覆盖另一项失败。依赖资源仍按已有借用顺序保留。整个关闭尝试共享一个 3 秒截止时间，不是面板和宿主各获 3 秒。超时仅表示本次等待结束，后台工作与句柄仍归原所有者；再次请求观察或重试同一资源，不创建替代者。

继续保留现有清理失败锁存；不能将消费过的失败句柄误认为成功。永久清理失败可能无法通过重试退出恢复，本增量不提供无证据的强制成功。托盘成功创建仅证明 API 接受，不证明图标对用户可见；Explorer 重启后的图标恢复和入口可达性留待新的现场验证。

## 暂停、恢复与队列反馈

- 重启总是暂停；不记忆自动开启。托盘与主窗口同时显示“正在收录 / 已暂停 / 已停止新增 / 异常 / 正在退出”。
- 状态命令返回并重新读取权威状态后才更新按钮。使用明确的 enabled 布尔值；重复暂停/开始不变成双重 toggle。并发请求由宿主串行决策，迟到 revision 不回退界面。
- 沿用现有暂停与 commit gate 语义：先提交取得 gate 的条目可以完成；暂停确认后，旧 epoch 未提交工作不得再入库。界面说明“暂停会取消尚未保存的旧收录任务”，显示 cancelled 变化，不承诺暂停会保存队列。
- 排除变更沿用同一策略边界，保存前明确提示未提交任务会取消；已提交历史不会被删除。
- 存储失败的“重试保存”与普通“开始收录”必须区别。退出失败期间，重试只排空原队列，不能重新开放收录或复制；重试保存成功后仍需确认全部关闭结果。
- 暂停收录时仍可显式复制历史，保留现有内部写入登记与过滤；不将隐藏窗口或暂停等同于退出。

## 最小应用排除与待定选择

身份继续使用规范化的完整 Windows exe 路径，上限沿用 32 条；匹配沿用 Windows ordinal Unicode 不区分大小写规则。只提供路径列表、添加、移除、应用；不引入运行中进程枚举、前台窗口识别、通配符、应用名或发布者规则。

已知 owner 与排除路径匹配则跳过；列表非空而 owner 路径未知或无效也跳过，反馈“来源无法确认，按排除规则跳过”。列表为空时允许未知来源入库，并保留来源未知标签。内部来源标记及隐私标记继续走现有判断，不被设置 UI 绕过。

这是按 owner 路径控制进入历史的规则，不是应用身份认证，也不是“不读取剪贴板”的保证：当前过滤在 worker 返回快照后及提交前执行。路径别名、应用移动及代理进程可能影响识别；本增量不承诺辨识网页域名、应用包或同一二进制的所有别名。

| 选择 | 保存与启动行为 | 代价 |
| --- | --- | --- |
| A：仅本次运行 | 复用内存排除列表；重启为空，启动始终暂停，UI 明示“重启后失效” | 改动最少，但用户需每次重新配置隐私规则 |
| B：跨重启记住（推荐） | 当前 data-dir 下保存有版本的 settings.json；重启载入排除，仍暂停收录 | 新增持久格式及原子保存、损坏/失败/回退测试 |

用户已批准 B，避免重启后用户误以为排除仍然有效。它是明确新增的文件契约，不是数据库迁移。文件解析与保存由 config 层唯一负责；排除策略仍由现有 CaptureState 持有，界面不直接写文件。第一切片已接受的驻留与退出工作保持。

B 的最小格式为 `{"schema_version":1,"excluded_apps":[]}`，不保存 capture_enabled 或可编辑热键。文件不存在使用空列表；坏 JSON、非法路径、未知版本或未知字段保留原文件，阻止开始收录并显示设置错误，不静默改为空表。未实现的旧文档格式不视为已部署迁移来源。

保存顺序：验证与规范化 → 在后台写同目录临时文件 → 在策略 gate 下完成替换并发布新 epoch/列表 → 返回生效结果。不能在 GUI 消息线程执行文件 I/O。替换失败不发布新规则、不显示成功；若磁盘最终状态无法确认，停止接纳并显示错误，在核对重读前不恢复收录。崩溃发生在替换成功、内存发布前时，下次启动先加载文件且仍暂停。保存与退出互斥排序，退出封闭策略更新后不得再发布新规则。

设置出错的当前实例不直接覆盖损坏文件；最小恢复为保留文件、退出后由用户修正，再重新启动。该提案不授权助手读取或修复任何既有用户设置/历史库。

## 第二切片的文件与退出顺序

`config::SettingsFile` 独占格式、期望磁盘字节、同目录临时文件及 Windows 替换。已有文件使用 `ReplaceFileW`，首次保存用不覆盖目标的 `MoveFileExW`；临时内容先 `sync_all`，替换后重读核对。写入前发现外部改动、或替换失败后无法确认原字节保留时，当前实例阻止收录和后续覆盖。可靠确认原文件未变的替换失败可以重试，内存规则和 epoch 保持原样。重复路径按 Windows ordinal 不区分大小写合并；等价重复应用仍核对并保存文件，但不改 epoch。

保存准备在后台线程进行。最终替换与策略发布占用既有 commit gate，规则及 epoch 仍由 CaptureState 持有。退出 fence 与规则发布共用短暂的 state lock，不让 GUI 等待设置 I/O 或已有 commit：退出先到则不发布新规则；若替换已经在途，文件可能完成保存，但本次命令报错、当前收录保持关闭，并提示下次启动核对磁盘规则。统一退出在同一个截止时间内等待 settings_saving 结束，未确认结束不报告退出成功。此路径的重新启动仍先加载磁盘并保持暂停。

独立命令为 `get_settings_state` 和 `apply_excluded_apps`；`settings_changed` 仅携带严格 revision，界面读取权威快照并拒绝迟到 revision。快照包含当前列表、saving、blocked、错误及 owner 跳过原因。旧状态/复制/worker 消息未增加字段；快捷面板无设置编辑入口，宿主仍独立校验真实本地主窗口才能更改。

## 接口与兼容

旧 `get_status`、复制结果及 worker 协议保持原形。新增独立驻留/排除状态命令与 revision 事件，承载 tray 状态、退出阶段/错误、当前排除列表、保存模式及最近跳过原因；复用原收录状态作为唯一来源，不复制成另一个可写开关。

主窗口可设置排除和请求退出；快捷面板只读新增状态，继续使用现有面板命令。命令仍校验 Tauri 注入的真实窗口与本地 origin，不能接受客户端自报身份；托盘回调直接调用同一宿主动作。Rust/TypeScript 契约及共用 JSON fixture 同步更新。

前后端同包交付；旧客户端可继续调用旧命令，新客户端面对旧宿主时禁用 M2 并明确提示能力不可用。不得靠旧严格解析器忽略字段来假定兼容。无 SQL schema 变化；现有 history.sqlite3 不迁移。

采用 B 后，回退到 M1 的旧程序不会加载排除文件，不能承诺回退仍保护排除应用。回退先退出本程序并保留整个 data-dir，旧程序仍从暂停开始；用户需知晓规则未生效。未来更高版本 settings 不由 M2 降级重写。

托盘拟启用现有 Tauri 的 `tray-icon` feature。本机对应版本源码已确认该 feature 与托盘 API 存在，lock 也有相关包；这不证明所有编译依赖已缓存。只允许后续离线检查；缺缓存即报告，不安装、联网取包或手改 lock。前端依赖如需复用，先做任务目录中的隔离副本，不共享可写 node_modules，也不修改封存来源。
