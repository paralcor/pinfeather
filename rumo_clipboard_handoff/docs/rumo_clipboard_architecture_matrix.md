## 3. 重点机制与取舍

### 3.1 格式与载荷

- A／G 拟将摘要与多格式载荷分开，避免列表刷新全量加载大图片、富文本或 CAD 格式数据；是否降低峰值需测量。
- B 拟以 MIME 字典保存格式并按需转码。文本可做 UTF-8 校验，私有二进制格式不能据此认定跨系统兼容，恢复范围待定。
- 表中的 `WM_RENDERFORMAT` 是延迟渲染候选机制，是否避免读取阻塞还取决于抓取线程、目标应用和超时设计。

### 3.2 监听与内部写入

- A／B／E／G 可评估 `Clipboard Viewer Ignore` 及 Windows 历史／云端排除标记；不同标记的范围与值需要分别处理。
- B 可用 `GetClipboardSequenceNumber` 辅助追踪变化。它不识别来源，也不能替代内容去重、快照一致性与重试设计。
- 状态保护与格式标记的组合需要验证异步事件，不作为“不会漏记或死锁”的保证。

### 3.3 焦点与输入

- A 保留修改前台锁超时、`AttachThreadInput`、`BringWindowToTop` 和 `SetForegroundWindow` 的组合设想，其限制和系统副作用待验证。
- A 的合成 KeyUp 与 B 的松键等待是不同策略；50ms 等待后再强制释放仅为候选流程，具体默认行为待定。
- 权限与架构位数分别评估：提权辅助进程需要用户授权和身份校验，64 位辅助进程不等于获得更高权限。

### 3.4 脚本与规则

- B 可评估 JavaScript 动作与 CLI 分帧；文件、网络和命令能力需要单独的访问控制、隔离和终止设计。
- E 可评估 Roslyn 编译宏。动态编译和类型检查不自动提供沙箱、可靠卸载或有界执行。

### 3.5 配对与同步

- C 可组合 mDNS 与候选地址交换，在组播不可用时尝试单播；不能保证绕过路由、NAT 或防火墙。
- `Pairing V3` 为暂定设计名，Intent／Proof／Commit、SAS／HMAC 和 AEAD 仍需完整的密钥、认证、重放保护与恢复设计。
- LWW、条目合并及当前剪贴板覆盖是不同问题；最终一致性和防循环行为需两机实测。

### 3.6 交互与 AI 工具

- D 的参数插槽可与材料集合组合；模板预览、缺参、取消和普通文本渲染需形成契约。
- C 的 OCR 和 MCP 为可组合能力，不代表接入模型即可正确理解内容。
- MCP 应明确开放的材料范围与撤销方式，行为注解不能代替授权；只读访问和写入工具分开评估。

## 4. 风险与验证重点

1. 历史及云端标记：回贴时是否影响 Windows 历史与同步，需依据标记语义和用户策略验证。
2. 系统钩子：可能增加安全软件拦截和兼容风险，优先比较无进程注入的监听方式，具体选型待定。
3. 输入法：检查组合输入与回贴时序；强制清空 Composition 可能丢失未提交文字，不作为默认保护行为。
4. 多网卡与虚拟机：分别测试发现、单播可达、配对、断线重连和地址变更，提供可见的失败状态。
