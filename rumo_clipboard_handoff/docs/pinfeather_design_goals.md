# 片羽 Pinfeather：项目设计目标

记录日期：2026-10-22。状态：产品目标与设计基线，尚未实现。

本文记录片羽要做成什么，以及判断设计是否符合方向的依据。已确认方向来自[项目交接文档](pinfeather_project_handoff.md)及首轮工作范围；用户场景、体验原则和能力细节是据此整理的设计建议。执行顺序与技术验收见[首轮任务清单](pinfeather_first_iteration_tasks.md)，界面参考见[原型说明](../../design/prototype/README.md)。

## 1. 要做成什么

**片羽是一款 Windows 优先的剪贴板工具，帮助用户找回、复用和流转复制过的内容，并把零散材料整理成可以交给人或 AI 工具使用的上下文。**

日常使用时，片羽在后台保存允许收录的复制内容。用户需要一段文字、链接、代码或截图时，能随手唤出面板、找到内容，再回到正在工作的应用中使用。围绕同一项任务的材料可以进一步整理成集合，配上常用指令，预览后复制、导出，或让获准的工具读取。跨设备能力从两台 Windows 电脑的局域网流转开始，安排在单机能力之后。

项目目标是成为可以长期发展的独立产品。日常剪贴板体验是基础，材料整理、AI 协作和跨设备流转在这条基础上逐步建立。

## 2. 已经确定的方向

| 方面 | 设计方向 |
| --- | --- |
| 产品主体 | 围绕剪贴板中的内容，优先解决找回与复用 |
| 首发平台 | Windows 11 25H2/26H2 Home/Pro x64；先验本机，未测组合不标兼容 |
| 首轮工作 | 修订规格，跑通监听 → 存储 → 搜索 → 快捷面板 → 回贴 |
| 公开预览重点 | 单机剪贴板与材料整理；保留集合、参数模板、CLI/MCP 三项 AI 协作能力 |
| 跨设备起点 | 后续实现两台 Windows 的局域网互通 |
| 推进方式 | 按阶段验收，先证明核心链路可用，再扩展能力 |

以上方向不代表界面原型中的每项操作、默认值或候选方案中的每种技术都已确认。

## 3. 为谁解决什么问题

建议先面向经常在多个应用之间处理文字、链接、代码、日志和截图的 Windows 用户。具体优先服务哪类用户，仍需试用反馈确认。

| 常见问题 | 希望用户获得的结果 |
| --- | --- |
| 刚复制过的内容被下一次复制覆盖 | 能找回允许收录的历史，不必重新寻找来源 |
| 记得内容的一小部分，想不起在哪复制 | 用中文一两个字、英文片段、代码或链接中的一部分找到它 |
| 在浏览器、编辑器、终端之间来回复用内容 | 唤出面板后直接选择，尽快回到原来的工作位置 |
| 一项任务的材料分散在多处 | 把相关片段放进集合，整理顺序并预览完整输出 |
| 每次给 AI 都要重新拼背景和重复要求 | 复用材料与指令，只填写每次变化的参数 |
| 希望 AI 工具读取指定材料 | 主动开放选定集合，清楚知道开放范围并能撤销 |
| 两台电脑间反复搬运内容 | 配对后流转需要的材料，连接和传输状态可见 |

## 4. 目标使用流程

### 4.1 随手找回与复用

用户在真实应用里复制内容，片羽按收录规则保存。需要复用时，通过快捷键或托盘唤出面板，输入记得的片段、浏览预览并选择条目，然后回到目标应用。

这条流程应保持简短：主要操作可以用键盘完成，不必先打开完整管理窗口。需要纯文本时有明确入口；无法确认回贴目标时停止自动回贴，准确提示结果，并在内容确实写入剪贴板后提供手动粘贴路径。

### 4.2 围绕任务整理材料

用户把相关历史片段选入一个集合，调整顺序，按需要编辑副本，再选择常用指令模板、填写参数。交付前能看到最终文本，然后合并复制或导出 Markdown。

设计建议是让集合材料独立保留：历史清理不会使任务材料消失，集合编辑也不改变历史原文。文字和链接先贯通完整流程；图片先提供历史预览、独立复制和导出，图文混合交付按实际目标工具验证。

### 4.3 向 AI 工具交付材料

用户主动选择开放哪些集合。CLI 和 MCP 使用同一份材料与访问规则，先提供列表、读取和导出等最小能力；AI 工具默认不能读取普通历史。

用户能查看和撤销开放范围。界面说明材料交给外部工具后，工具可能再发送给模型服务。片羽自身的基础剪贴板能力应能独立使用，无需内置模型或付费 API。

### 4.4 在两台设备之间流转

用户明确配对两台 Windows 设备后，在局域网中加密传输文字、链接和图片，并主动发送集合。连接中断和恢复、暂停、撤销配对应有可理解的状态。

首轮同步设计建议只传播新增条目与主动发送的集合，不传播删除；接收内容进入历史，由用户决定是否使用，不自动覆盖接收端当前剪贴板。具体协议与安全机制另行验证。

## 5. 体验与质量目标

以下是评估设计和实现的基线，达成情况必须由测试与真实使用证明。

| 目标 | 设计要求 | 如何判断 |
| --- | --- | --- |
| 找得到 | 中文一两个字也能检索；覆盖英文、代码、URL，检索完整内容 | 有固定样本与预期结果，结合真实历史规模验证 |
| 回贴可信 | 目标变化时不报告成功；区分已复制、已发送指令与实际粘贴结果 | 在浏览器、编辑器、终端及后续办公软件中实测失败和成功路径 |
| 收录可靠 | 外部复制与片羽内部写入分开识别；失败、过载和无法抓取的情况有记录 | 快速复制与交错写入逐条核对，不以静默丢弃换取表面稳定 |
| 使用顺手 | 快捷面板承担高频找回，管理窗口承担整理和设置；键盘路径完整 | 观察完成常见任务所需的操作，检查快捷键冲突与焦点行为 |
| 状态真实 | 暂停、排除、读取失败、未自动回贴、工具开放与同步状态表达准确 | 提示与实际行为对应，不以按钮动画或 toast 代替结果 |
| 数据可控 | 可暂停收录、排除应用、删除历史、设置保留规则；遵守历史排除标记 | 验证规则及其例外；集合保留和收藏策略单独明确 |
| 日常驻留负担可接受 | 不阻塞正在使用的应用，唤出和搜索及时，长期运行资源稳定 | 测冷启动、热唤出、搜索和包含所属 WebView2 进程的内存，不提前承诺数字 |
| 内容能持续使用 | 重启后数据正确，后续升级、备份和恢复有明确路径 | 按阶段验证重启一致性、升级与恢复；不把存储成功等同于恢复能力已完成 |

可靠性边界需要如实说明：剪贴板抓取前已被覆盖的内容不能凭序列号还原，发送粘贴按键也不能证明目标应用已消费内容。出现限制时保留证据并改进设计，不作无法验证的保证。

视觉建议沿用现有原型：中性灰阶为主，晨曦粉用于主操作、选中和焦点；文字与预览保持清晰，减少装饰对内容的干扰。浅色、深色、密度、分栏和动态效果围绕实际使用需要验证。具体快捷键、悬停选中与单击回贴行为保留为确认项。

## 6. 分阶段做成什么

| 阶段 | 用户能获得什么 | 阶段完成的依据 |
| --- | --- | --- |
| 当前：核心纵向原型 | 在真实 Windows 应用中验证复制、保存、搜索、唤出和回贴 | 首轮任务清单通过，重点覆盖 R1/R2/R6，并记录启动与内存基线 |
| 内部试用：单机基础 | 文字、链接、图片历史，搜索、预览、收藏、删除，纯文本粘贴，托盘、快捷键、暂停与排除 | 浏览器、编辑器、终端、办公软件可用，重启数据正确，无内部写入循环收录 |
| 首个公开预览：基础与 AI 协作 | 集合整理、合并复制、Markdown 导出、参数模板、最小 CLI/MCP 读取 | 同一集合贯通界面、导出与接口；模板结果可预览，至少一个真实 MCP 客户端接入 |
| 后续预览：局域网互通 | 两台 Windows 配对与内容流转 | 断线恢复无循环、无重复；撤销配对停止传输，远端接收不覆盖当前剪贴板 |
| 稳定版本 | 经持续使用打磨的搜索、交互、性能与数据维护能力 | 连续真实使用一周并关闭关键问题，完成备份恢复与升级验证 |

阶段按验收结果推进，不在目标文档中承诺日历工期。核心原型通过后仍需完成内部试用剩余能力，才能宣称该阶段完成。

## 7. 暂不扩展的方向

手机与其他桌面平台、互联网同步、自动抓取完整 AI 对话、迁移模型内部会话、插件市场、通用脚本引擎、OCR 和语义搜索，保留为后续评估项。识别、翻译、改写等内容处理能力也需另定需求与接入方式，不能从 README 的愿景直接推导为首版交付承诺。

本轮先验证单机链路，集合、模板、CLI/MCP 和同步在链路通过后开展。七份候选方案中的看板、队列、动态规则等能力，只有在具体用户问题和验收标准明确后才进入计划。

## 8. 仍需确认的产品问题

- 优先服务的细分用户与最高频的三个任务。
- 已确认普通权限运行；管理员或权限不明目标只提供手动粘贴。Windows 目标范围已定，逐组合兼容性仍待实测。
- 历史容量、默认保留时长、去重和收藏规则，以及图片与富文本的保真范围。
- 原型中的默认快捷键、单击回贴、悬停选中等交互细节。
- 首批 AI 客户端、开放集合的访问约定，以及图片材料如何交付。
- 同步的身份、配对、冲突与恢复规则，以及真实两机验收环境。
- 性能预算、长期试用反馈与商业化方式。

技术选型、实现与验收以修订后的规格为准；本文件用于保持产品目标一致。扩大阶段范围或改变已确认方向时，同步更新交接文档和相应任务清单。
