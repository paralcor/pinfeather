## 1. 本轮目标与边界

用 Tauri + Rust + React/TypeScript 跑通：**真实复制 → 监听 → 本地存储 → 搜索 → 快捷面板 → 回贴到原应用**。

已确认的方向：Windows 优先、剪贴板为主体、本地优先；先验证单机链路。集合、模板、CLI/MCP、局域网同步在这条线通过后再开展。本轮为后续内部试用提供技术证据，不等于完成交接文档 4.2 节的整个内部试用阶段。

| 本轮必须完成 | 后续阶段再做 |
| --- | --- |
| 修订原 MVP，给 R1–R8 安排修正或验证，冻结 Windows 支持范围 | 集合、参数模板、CLI/MCP、同步的实现 |
| 文字、链接的监听、持久化、搜索、预览和纯文本回贴 | 集合整理、合并复制、Markdown 导出、AI 客户端接入 |
| 验证同一条目保存多格式；用图片样本检查格式和载荷路径 | 完整图片历史体验、图片回贴及全部富文本保真 |
| 快捷面板、全局快捷键、托盘退出、暂停、最小应用排除 | 完整管理窗口、收藏与清理设置、开机启动等内部试用功能 |
| 浏览器、编辑器、终端中的真实验收及资源测量 | 办公软件完整验收、长期使用、升级与备份恢复验收 |

原型中的集合、模板、AI 与设备页面不作为本轮必须实现的页面。候选方案 A–G 仅在相关任务需要时查阅，不整体合并。

**R2 的证据边界：** Windows 剪贴板保存当前内容，序列号表示变化，不能重建在抓取前已被覆盖的中间载荷；见 [GetClipboardSequenceNumber](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getclipboardsequencenumber)。验收必须区分“已观察且可读取却被实现丢弃”与“操作系统已覆盖、未取得快照”。后者也要记录为限制，若达不到约定的快速复制标准，应留作阻塞项并调整设计，不能靠缩小统计口径宣称完全不漏记。

网页原型检查使用无头 Playwright；真实 Windows 应用的焦点、输入法和回贴另做人工验收。不得让网页脚本接管真实鼠标键盘。系统行为的自动测试需要隔离环境和对应授权，不能用模拟记事本结果代替真机证据。

- [ ] **固定环境和构建。** 使用 release 构建；记录机器 CPU、内存、存储、系统/应用/WebView2 版本、数据规模及测量工具。开发服务器和 debug 构建的数字另列。
- [ ] **冷启动。** 定义为片羽及其所属 WebView2 进程全部退出后，到快捷入口可用、到首次面板内容可交互两个时点；区分“新进程启动”与重启系统后的首次启动。至少测 10 次，保留逐次数据和中位数/最大值。
- [ ] **热唤出。** 后台已驻留，从触发快捷键到面板可输入、首批结果可选择；至少测 50 次，报告 p50/p95/最大值，注明是否预热与面板数据规模。
- [ ] **搜索。** 建议用 1,000、10,000、100,000 条合成记录，固定文本长度分布；分别测中文一字/二字、长片段、英文、代码和 URL，记录正确性以及查询耗时和用户可见延迟。任何未完成规模标“未测”。
- [ ] **内存。** 分别测启动稳定后、隐藏空闲、面板显示、连续复制/搜索后、反复打开关闭后的数值及峰值；定义空闲稳定的采样时长。汇总 Rust 宿主与归属片羽的 WebView2 浏览器/渲染/GPU 等进程，避免混入其他应用的 WebView2 或重复计数。
- [ ] **内存口径。** 工作集与 Private Bytes 分别记录，注明采样间隔；共享页求和的重复计算限制单独说明。不通过主动裁剪工作集制造低内存结论。
- [ ] **形成结论。** 先报告原始基线与瓶颈，再确定进入内部试用的性能预算。旧规格的 12–18 MB、低于 50 ms 不作为已达成指标；本轮不预设未经讨论的硬性数字。
